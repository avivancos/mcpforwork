# S6.10 — API structured error kinds + action test gaps

**Epic:** Sprint 6 / self-host E2E — hardening follow-up (from S6.6b review)
**Estimated effort:** ~1.5 h

## Goal

Replace the `"not found" in error` string-sniffing in
`entrypoints/api/app.py::_action_response` with structured error kinds, and
close the test gaps the S6.6b review flagged.

## Spec

- Services (`review`, `apply`) return an error kind alongside the message
  (e.g. `{"error": ..., "kind": "not_found" | "invalid_state" | ...}`); the
  API maps kinds → status codes (404/400). No substring matching.
- Add the missing tests:
  - outcome route with the application in `filling` → 400 (invalid
    transition via API, not just via approve).
  - foreign-match 404 for discard / restore / outcome (approve already has
    one).
  - `restore_match` audit row asserted.
  - profile POST anti-smuggling: a body with raw intake keys (`full_name`,
    `label`, `min_salary_amount`) does NOT write those columns.

## Files to create/modify

- `src/mcpforwork/services/review.py`, `services/apply.py` (error kinds)
- `src/mcpforwork/entrypoints/api/app.py` (kind → status mapping)
- `tests/test_match_actions_api.py` (+ the MCP tools' error paths stay
  message-only — the kind is additive)
