# S3.2 — submit_asset + versioning + print template

**Epic:** Sprint 3 — Assets: briefs + honesty engine
**Estimated effort:** ~3 h
**State:** pending

## Goal

Store and version the drafts the client LLM produces. Assets are markdown/HTML;
PDF is browser-print (print-CSS), no server rendering (MVP bias).

## Spec

- Migration v5: `generated_assets` (id, user_id, finding_id → explore_findings,
  asset_type, content, version, created_at) + FORCE RLS + fail-closed policy.
  UNIQUE(user_id, finding_id, asset_type, version). Same-shape PG twin.
- `services/assets.py`: `submit_asset(uow, user_id, finding_id, asset_type,
  content)` → auto-increments version per (finding, type); returns
  {asset_id, version}. `get_assets(uow, user_id, finding_id, asset_type=None)`
  → newest first. Unknown finding → `{error}` (ownership scoped by user_id).
- A minimal print-CSS HTML template served in the brief's `format` block
  (static string in domain/brief.py — data, not a rendering engine).
- MCP tools `submit_asset`, `get_assets`.
