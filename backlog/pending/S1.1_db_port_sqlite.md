# S1.1 — DB port + SQLite adapter + migration runner

**Epic:** Sprint 1 — Data core (organ transplants)
**Estimated effort:** ~4 h
**State:** pending

## Goal

The persistence foundation: the Database port, the dual-dialect adapter core,
and the migration runner — ported from startup-jobs-radar's battle-tested
raw-SQL layer WITH its tests, so years of stepped-on landmines (FK-safe
recreation, lazy import cycle, `?`→`%s` adaptation) come along.

## Spec

**Donor (read-only reference):** `~/Desarrollo/startup-jobs-radar/`
- `src/radar/backend.py` (188 LOC) — dialect adapter: `connect(url)` picks
  dialect by URL prefix; `is_postgres(conn)` via
  `isinstance(conn, sqlite3.Connection)` so psycopg is never imported on
  SQLite-only installs (TYPE_CHECKING-only at module top); uniform
  `execute/fetchone/fetchall` with `?`→`%s` translation; `last_insert_id`
  handling `lastrowid` vs `RETURNING id`.
- `src/radar/db.py` (826 LOC) — port ONLY the migration-runner pattern:
  SQLite walks `PRAGMA user_version` over an inline `MIGRATIONS: dict[int,str]`
  with a `_FK_RECREATE_MIGRATIONS` set toggling `PRAGMA foreign_keys OFF`
  around table-recreation migrations; Postgres reads `migrations/*.sql`,
  skips versions in `schema_migrations`, splits statements with the
  dollar-quote-aware parser (psycopg has no executescript).
- Tests: `tests/test_db_backends.py`.

**Target shape (adapt, don't copy verbatim):**
- `ports/db.py` — `Database`/`UoW` Protocol (the seam named in §Architecture
  spec; this is the sanctioned single-implementation-for-now Protocol).
- `adapters/db/` — `backend.py` equivalent + `migrations.py` runner +
  `schema.sql` v1 (minimal: `users`, `audit_log`; domain tables arrive with
  S1.3/S1.4 as migrations).
- SQLite path fully working this card; Postgres connect function may raise
  `NotImplementedError` until S1.2 — do NOT stub psycopg.
