# W5.2 — Wire `npm run test` into the `web` CI job

**Epic:** Web / public site (commercial v1)
**Owner:** whoever owns `.github/workflows/ci.yml` (the server/CI track — the web
loop is boundary-forbidden from editing that file).
**Estimated effort:** ~5 min (one CI step).

> Follow-up seeded by the W5.1 final-review gate. The test-auditor raised a P1:
> `web/src/lib/safeRedirect.ts` (`isSafeBillingUrl`, the open-redirect guard on
> the checkout money path) is a runtime security control the type system can't
> express, so it needs a check that re-runs on every change. W5.1 landed that
> check as a **committed, zero-dependency `node:test`** suite
> (`web/src/lib/safeRedirect.test.ts`, run via `npm run test`), which is
> re-runnable today. What's missing is the CI wiring so a future regression
> actually fails a build — and that requires editing `ci.yml`, which the web
> loop must not touch. Hence this card.

## Goal

Add one step to the **`web`** job in `.github/workflows/ci.yml` so the guard's
test suite runs on every push/PR, alongside the existing no-LLM-deps / typecheck
/ build steps.

## Change (exact)

In the `web:` job, after "Typecheck" (or anywhere in that job), add:

```yaml
      - name: Test
        run: npm run test
```

`npm run test` = `node --test` (Node 24 on CI, type-stripping on by default —
auto-discovers `web/src/**/*.test.ts`). No new dependency, no config file; uses
Node stdlib `node:test` + `node:assert`. Already green locally.

## Why this isn't in W5.1

The web track is hard-forbidden from editing `.github/workflows/ci.yml` (the
server loop owns it). W5.1 therefore shipped the re-runnable test + `npm test`
script and carded the CI step here — the test-auditor's sanctioned disposition
for "the test exists and re-runs, but its CI enforcement crosses a track
boundary."

## Definition of Done

- [ ] `web` job in `ci.yml` runs `npm run test`; a deliberately broken
      `isSafeBillingUrl` (e.g. drop the `protocol` check) fails that job
- [ ] No change to the Python `checks` job
