# S2.2 — Profile MCP tools

**Epic:** Sprint 2 — MCP v1 (profile + hunt)
**Estimated effort:** ~2 h
**State:** pending

## Goal

Expose the S1.3 profile services as MCP tools so the client LLM can read and
build the user's profile during `/setup`. Thin wrappers only — validation,
privacy, and persistence already live in `services/profiles.py`.

## Spec

Tools (each opens `_uow()`, calls the service, commits on mutation, attaches
`next_action`, returns JSON):
- `get_profile(profile_id?)` → active or given profile (JSON fields parsed).
- `update_profile(patch)` / `update_profile(profile_id, patch)` — partial;
  validation errors surface as `{error: ...}` not exceptions.
- `list_profiles()`; `set_active_profile(profile_id)`.
- `add_achievements(profile_id, items)`; `set_style_profile(profile_id,
  writing_sample, directives?)`.
- `import_from_url_findings(url, fields)` — apply client-LLM-extracted
  structured fields (LinkedIn/GitHub/portfolio) to the active profile as an
  update, auditing the source `url` for provenance. (Full guided import UX is
  S5.2; this is the persistence tool it will call.)

Ownership + privacy are already enforced in the service layer (a foreign
profile_id is rejected; min-salary redaction is on `export_for_brief`).

## Files to create/modify

- `src/mcpforwork/entrypoints/mcp/server.py` — add the profile tools
- `tests/test_mcp_profile_tools.py` — NEW (drive tools over a real tmp DB)

## Definition of Done

- [ ] Create → read → update → set-active round-trip through the tools on a
      real tmp DB (no mocks)
- [ ] Validation failure returns `{error}` (tool never raises to the client)
- [ ] `add_achievements` / `set_style_profile` reject a foreign profile_id
      (service ownership check) surfaced as `{error}`
- [ ] `import_from_url_findings` applies fields and audits the source url
- [ ] Targeted tests green; Final-review gate 4/4
