# S6.1c — Parity API hardening before hosted launch

**Epic:** Sprint 6 hosted alpha — the security controls the S6.1a/S6.1b gates
deferred (all NON-blocking on self-host; REQUIRED before the real mailer /
Postgres multi-tenant deploy).
**Estimated effort:** ~3–4 h (likely split)
**State:** pending

## Why
S6.1b shipped the auth API on self-host terms (ConsoleMailer, SQLite, localhost).
Three gate reviewers signed off on that basis while explicitly carrying the
controls below to a hosted-launch card. None may be skipped before the API faces
the public internet with a real email sender and a shared Postgres.

## Controls (each with a real test)
- **Rate limiting** — per-IP and per-email throttle on `POST /v1/auth/magic-link`
  (open account creation + arbitrary-address emailing = spam/enumeration/DoS once
  a real mailer is wired).
- **PG tenant isolation over HTTP** — the API must `connect()` as the restricted
  `app` role with `run_migrations=False` (the app role lacks DDL); add a
  fail-closed assertion that the request-path connection is non-privileged
  (no BYPASSRLS), and a **live-PG cross-tenant API test** (user A's cookie cannot
  read/mutate user B via any route). This closes the DoD's "both backends
  through the API" gap S6.1b left on SQLite only.
- **Host/origin fail-closed** — `_public_base_url` currently falls back to the
  spoofable `request.base_url` when `MCPFORWORK_PUBLIC_BASE_URL` is unset; make
  it RAISE when a non-ConsoleMailer mailer is active, and mount Starlette
  `TrustedHostMiddleware` with an allowlist.
- **CSRF** — explicit CSRF tokens on the state-changing POSTs (export/delete/
  profile-write) beyond the current `SameSite=Lax` baseline; `__Host-` cookie
  prefix on the session cookie.
- **Session revocation** — a revocation store (or secret-rotation kill-switch) +
  a user-existence check in `read_session`/`_current_user` (a signed cookie for a
  deleted/erased user must stop authenticating before its 14-day expiry).
- **Account-existence non-disclosure** — the SELECT-vs-INSERT timing delta in
  `request_magic_link` is now a *remote* oracle; make the response near-constant-
  time / uniform.
- **Body-size cap** on `await request.json()` (unauthenticated route → memory DoS).
- **`users.id` reuse (SQLite)** — `AUTOINCREMENT` (or the existence check above),
  so a recycled rowid can't inherit a stale valid session.
- **Token-in-logs hygiene** — redeem token is in the GET URL; scrub access logs
  and/or add a POST-confirm redeem interstitial to defend against link prefetch.
- **Secret management** — `MCPFORWORK_SESSION_SECRET` from a secret manager, never
  logged, with a rotation runbook (rotation invalidates all sessions — the
  intended kill-switch).

## Definition of Done
- [ ] every control above implemented OR explicitly re-deferred with a written
      reason on this card; each implemented control has a real (zero-mock) test
- [ ] a live-PG cross-tenant API test proves isolation through the HTTP layer
- [ ] security-reviewer re-run PASS (same auth boundary)

## Separate follow-on (NOT this card): the remaining dashboard endpoints

`/v1/pipeline/stats`, `/v1/matches/{id}` + approve/discard/restore/outcome,
`/v1/connection`, `/v1/subscription`, `/v1/sessions` (+ revoke), `/v1/audit`,

(`Profile`, `PipelineItem`, `PipelineStats`, `MatchDetail`). `/v1/billing/session`
is S7.1 (Stripe). Card these as their own slices.
