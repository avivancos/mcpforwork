# S6.6c — Parity API: account endpoints + session store

**Epic:** Sprint 6 / self-host E2E — API parity (Phase 1 of the E2E plan)
**Estimated effort:** ~3.5 h

## Goal

The dashboard's account pages hit real endpoints: sessions list + revoke,
audit trail, connection status, honest self-host subscription/billing stubs.
This pulls the S6.1c session-revocation control forward: the sessions page
needs a real session store.

## Spec

- New `sessions` table (migration 9, BOTH dialects + PG RLS policy): id,
  user_id FK, created_at, last_seen, user_agent, revoked_at.
- `services/auth_session.py`: `issue_session` persists a sessions row and
  embeds the session id in the signed cookie; `read_session` returns
  (user_id, session_id); touch `last_seen` on read.
- `entrypoints/api/app.py::_current_user` gains a DB check: unknown session,
  revoked session, or deleted user → 401 (closes the deleted-user-cookie and
  SQLite rowid-reuse holes).
- Routes (session cookie required):
  - `GET /v1/sessions` → SessionInfo[] (id, device from user_agent, lastSeen
    ISO, current flag)
  - `POST /v1/sessions/{id}/revoke` → 204; revoking the CURRENT session also
    clears the cookie; revoking a foreign session → 404
  - `GET /v1/audit` → the user's audit rows, newest first (explicit user_id
    filter — audit_log is not RLS-forced), capped (e.g. 100)
  - `GET /v1/connection` → derived from the user's last MCP-side audit row
    (connected bool, client null, syncedMinAgo→ISO lastSeen) + additive
    `tenantEmail` field (the user's email — surfaces tenant mismatch)
  - `GET /v1/subscription` → static honest `{"status": "active",
    "trialDaysLeft": 0, "price": "self-host"}`
  - `POST /v1/billing/session` → `{"url": null}` (Stripe is S7.1, deferred)
- Live-PG arm: sessions table RLS (user A cannot read/revoke user B's
  session rows via the app role).
