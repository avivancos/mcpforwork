# S4.2 — report_apply_progress loop + resolve_field (progressive profiling)

**Epic:** Sprint 4 — Browser-apply orchestration
**Estimated effort:** ~3 h
**State:** pending

## Spec

- `services/apply.py`:
  - `report_apply_progress(uow, user_id, application_id, step_id,
    status: ok|blocked|mismatch, observed="")` — advances current_step on ok
    (returns next step or `{state: awaiting_human, next_action: request_submit}`
    when steps are exhausted); on mismatch returns a repair hint (re-read the
    page, adjust selector) and keeps the step; on blocked routes to the
    obstacle flow (S4.4 extends). Every report audited.
  - `resolve_field(uow, user_id, application_id, field_label, field_type="",
    options=None)` — deterministic answer from profile fields/form_answers
    (label-token match); if unknown → `{ask_user: true, suggestion?}`;
    `save_form_answer(...)` persists the human-confirmed answer to
    profiles.form_answers so it is never asked twice.
- MCP tools `report_apply_progress`, `resolve_field`, `save_form_answer`.

## Definition of Done

- [ ] ok advances; last ok → awaiting_human (NEVER submit-authorized here)
- [ ] mismatch keeps the step + returns repair; blocked pauses
- [ ] resolve_field answers from profile (email, name, notice period via
      form_answers); unknown → ask_user; saved answer is reused next time
- [ ] Foreign application_id rejected; audited; gate 4/4
