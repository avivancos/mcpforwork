# S6.7 — mcpforwork connect: agent-client config generator

**Epic:** MCP / CLI
**Estimated effort:** ~3 h

## Goal

Agent-agnostic onboarding: one CLI command prints the exact MCP client
configuration for each supported agent client, in both run modes. No manual
JSON editing, no per-client docs spelunking — `mcpforwork connect` emits the
block to paste (or the file path to write).

## Spec

`mcpforwork connect [--client claude-code|claude-desktop|cursor|codex|opencode] [--mode local|compose]`
in `entrypoints/cli/main.py` (stdlib, print-only, no new deps).

- `--mode local` (default): stdio configs launching
  `uvx --from mcpforwork mcpforwork-mcp`, in each client's native format:
  - `claude-code` → `.mcp.json` block
  - `claude-desktop` → `claude_desktop_config.json` block (with the macOS/
    Windows config path printed)
  - `cursor` → `.cursor/mcp.json` block
  - `codex` → `config.toml` block (`[mcp_servers.mcpforwork]`)
  - `opencode` → `opencode.json` block
- `--mode compose`: streamable-HTTP configs pointing at
  `http://localhost:8500/mcp` (the compose MCP service), each with the
  single-tenant caveat line (networked MCP shares the one local tenant —
  multi-tenant HTTP auth is hosted scope, ADR 0006).
- No `--client` → print all five, separated by headers.
- `mcpforwork init` keeps its current behavior but prints a pointer to
  `connect` at the end.
- Golden-output tests per client per mode: exact expected text snapshot
  (assert the full block, not substrings — config drift must fail loudly).
- Tests assert the emitted JSON blocks are valid JSON (parse them) and the
  TOML block parses with `tomllib`.

## Files to create/modify

- `src/mcpforwork/entrypoints/cli/main.py` — the `connect` subcommand
- `src/mcpforwork/entrypoints/cli/connect.py` — NEW: pure formatters
