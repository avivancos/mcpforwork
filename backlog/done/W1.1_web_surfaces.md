## Goal

Implement the three web surfaces of mcpfor.work as designed in the handoff
canvas: the marketing landing page (comp 2a), the docs shell + Quickstart
(3a), and the hosted dashboard 1.0 (4a/4c/4e recommended variants, with 4g/4h
mobile and 4i/4j dark). The dashboard is a **mirror and control panel, never a
workspace** (brief §2 — hard invariants).

## Spec

- **Stack (per ADR 0002):** Next.js App Router + TypeScript in top-level
  `web/`; no state library, no component kit, no Tailwind; server components +
  native `fetch`; plain CSS with custom properties for the token sheet.
- **Routes:** `/` landing · `/docs` quickstart · dashboard: `/login`,
  `/connect`, `/onboarding`, `/pipeline` (home), `/matches/[id]`, `/profile`,
  `/account/billing`, `/account/data`, `/account/sessions` (brief §5 table).
- **Comps are final intent** (handoff README): Geist / Geist Mono, stone
  neutrals, indigo `#4F46E5`; light + dark first-class; WCAG AA; onboarding +
  pipeline-read work at 390px.
- **Hard invariants (brief §2):** zero server-side LLM calls; zero LLM SDKs in
  the dependency tree (CI guard); no drafting/generate/chat UI; no browser
  automation; nothing load-bearing for self-host; autonomy always legible
  (read-only "Supervised" card); manual refresh + light polling only.
- **Data:** single seam `web/src/lib/api/` typed to the MCP tool shapes.
  `MCPFORWORK_API_URL` set → HTTP adapter against FastAPI parity endpoints
  (cookie-forwarded session); unset → in-memory fixtures adapter (Sofía Reyes
  seed) so the app runs and demos today.
- **Resolved decisions (do not re-litigate):** free trial then $5/mo; pipeline
  = compact table + "Needs you" (no kanban); "Synced N min ago"; Autopilot
  deferred to read-only indicator.

## API parity gaps (build dependency — flagged per brief §7)

`src/mcpforwork/entrypoints/api/` **does not exist** (Sprint 2 = MCP stdio
only). Every dashboard read/write is therefore a gap, to be carded in S6.x:

- Reads: `get_profile`, `list_matches`, `get_match`, `get_assets`,
  `pipeline_stats`, audit log, subscription status, sessions.
- Writes: profile create/update (tiers, achievements, style), `approve_match`,
  `discard_match`, `record_outcome`, GDPR export/delete, Stripe
  checkout/portal session creation.
- Auth: magic-link session (S6.1) and connector OAuth AS (S6.2).

The web app must not work around these gaps by reaching into the DB or
re-implementing domain logic — fixtures adapter only.

### S6.x API/security contract (binding — surfaced by the final-review gate)

The UI's shape creates obligations the parity API MUST satisfy; recorded here
so they are structural, not folklore:

- **Auth, fail-closed.** Every `/v1/*` endpoint authenticates the session and
  returns 401 when absent — the web layer performs no auth (server actions in
  `web/src/lib/actions.ts` are public POSTs); the API is the sole enforcement
  point. Add a UX route-guard once sessions exist (S6.1). Session cookie:
  `HttpOnly`, `Secure`, `SameSite=Lax`.
- **Profile PATCH allowlist + email re-verification.** `POST /v1/profile` takes
  a partial; the API must whitelist fields server-side (the action already
  strips to scalar Tier-1 fields, but the API cannot trust the client) and
  require email re-verification on change (else: change email → magic link →
  account takeover).
- **Account deletion** executes only on an emailed, single-use, expiring
  confirmation token (the type-to-confirm is client UX only; the "nothing is
  removed until you click the email" copy is the real contract).
- **Magic-link** endpoint: per-email + per-IP rate limiting; uniform response
  regardless of account existence (the form already avoids enumeration).
- **Adapter contract:** `getMatch` 404 → `null` (done in `http.ts`); writes
  return 204 or JSON; `postingUrl` scheme validated to `http(s):` before it is
  rendered as an `href` (real data is scraped/attacker-influenced); narrow the
  forwarded cookie to the named session cookie; keep the fetch timeout, add no
  retry (non-idempotent POSTs).
- **Security headers** (S6.x, once a cookie exists): `frame-ancestors 'none'`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
- **Fixtures never seed real personal data** (shared process-global demo store).
- **Deploy note:** dashboard routes are `force-dynamic`; set `MCPFORWORK_API_URL`
  so the seam flips to HTTP. Production without it throws unless
  `MCPFORWORK_FIXTURES=1` is set (deliberate public demo).
