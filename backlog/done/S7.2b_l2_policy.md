# S7.2b — Autopilot L2: recorded policy + safe-board queue

**Epic:** Apply / autopilot
**Estimated effort:** ~4 h

## Goal

L2 autopilot: the human records an autopilot policy (min score, daily cap)
via the dashboard; the agent can then submit — without per-application
approval — applications on `auto_apply_safe` boards that meet the policy,
until the cap. Every authorization carries a criteria-snapshot audit row.
Consent writes stay API-only (ADR 0005); the MCP reads policy, never writes.

## Spec

- New append-only table `autopilot_policy` (both dialects + PG RLS):
  `id, user_id, enabled, min_score, max_per_day, created_at, revoked_at`.
  Active policy = newest non-revoked row for the user. Writes ONLY via
  `PUT /v1/autopilot/policy` (human session; validates 0≤min_score≤100,
  1≤max_per_day≤50) and `POST /v1/autopilot/policy/revoke`.
- `services/autopilot.py` gains a pure `evaluate(policy, finding, source,
  authorized_today, now)` helper returning a decision + criteria snapshot.
- MCP read-only tools: `get_autopilot_policy`, `autopilot_queue` — the
  queue is a QUERY, not a table: approved matches on `auto_apply_safe`
  sources, `score ≥ min_score`, not dedup-blocked, no open application.
  One service function shared with the dashboard.
- `request_submit` decision order: L1 approval → else L2 policy (active AND
  source `auto_apply_safe` AND score ≥ min AND authorized-today < cap) →
  else `await_human`. Every L2 authorization writes an audit row with the
  criteria snapshot `{policy_id, score, source_slug, cap_used, decision}`
  and flips `consent_level=2` atomically (same exactly-once pattern as L1).
- UTC daily-cap window normalized (ADR 0001 follow-up, now load-bearing):
  "today" = UTC calendar day, with a test pinning the boundary.
- Structural tests: refusal when source not-safe / below-score / cap-hit /
  policy-revoked-mid-batch; MCP entrypoint source never references policy
  writes (extend the CI consent grep: policy-write SQL only in
  `services/autopilot.py` + the API route module).
- Guidance + `/apply` prompt gain L1/L2 branches (when to use
  `autopilot_queue`, what `submit_authorized` under L2 means).

## Improvements noted

- `evaluate` counts the cap from audit_log detail LIKE '%"level": 2%' — a
  pre-filter both dialects evaluate as text; if a third consent level ever
  exists the marker stays unambiguous (JSON key+value).
- Guidance deliberately avoids the literal decision verb so the CI
  consent-verb grep keeps full strength (the response's `instruction` field
  carries the per-decision directive).
