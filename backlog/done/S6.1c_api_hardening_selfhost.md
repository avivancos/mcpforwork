# S6.1c — API hardening, re-scoped for self-host

**Epic:** Sprint 6 / self-host E2E — Phase 2 of the E2E plan. This REPLACES
the hosted-oriented `S6.1c_api_hardening_hosted.md`: the hosted launch is out
of scope, so each originally-deferred control is either implemented on
self-host terms below or re-deferred in writing with its reason.
**Estimated effort:** ~2.5 h

## Implemented on this card

- **Body-size cap** on body-carrying methods (reject > 64 KB with 413). A
  pure-ASGI middleware: fast path on the declared Content-Length, plus a
  stream-counting guard for chunked bodies with no length (the
  unauthenticated magic-link POST buffers `await request.json()` — memory
  DoS). Tests: declared-length over-cap → 413, chunked over-cap → 413,
  exact-boundary body passes.
- **`TrustedHostMiddleware` host allowlist**, env-driven via
  `MCPFORWORK_ALLOWED_HOSTS` (comma-separated). Kills DNS rebinding on LAN
  self-host. Default: `localhost,127.0.0.1,testserver` (testserver is the
  httpx dummy host — never resolves, no rebinding surface; IPv6 `::1`
  excluded on purpose — TrustedHost splits Host on `:` so a bracketed IPv6
  literal could never match). Tests: bad Host → 400; env override
  narrows/widens.
- **`MCPFORWORK_COOKIE_SECURE`** env (default `1`): `=0` is the documented
  escape hatch for LAN-http self-host, where a `Secure` cookie is never
  stored and magic-link login could not work. Tests: Secure present by
  default, absent under the escape hatch.
- **Live-PG cross-tenant API test through the HTTP layer** (the original
  card's headline DoD; Phase 1 proved the service-level filters, this proves
  the whole request path): the API connects as the restricted `app` role —
  new `MCPFORWORK_DB_RUN_MIGRATIONS=0` config (default 1 keeps self-host
  SQLite auto-migrate ergonomics; the app role cannot run DDL) — two real
  magic-link logins, user A cannot read/act on user B via any route, plus a
  fail-closed assertion that the request-path role is non-privileged
  (no BYPASSRLS).

## Re-deferred in writing (hosted scope — reasons)

- **Magic-link rate limiting** — the only mailer is ConsoleMailer (delivers
  to the server's own console): there is no real sender to abuse and nothing
  to enumerate on a single-user self-host. Re-open with the hosted mailer.
- **Host/origin fail-closed raise when a non-ConsoleMailer is active** —
  there is no non-Console mailer yet; the guard would be dead code. Rides
  the hosted mailer card.
- **CSRF tokens + `__Host-` cookie prefix** — the dashboard is same-origin
  fetch with a `SameSite=Lax` + `HttpOnly` cookie; `__Host-` requires
  `Secure`, which the documented LAN-http escape hatch turns off. Hosted
  scope.
- **Timing-uniform magic-link responses** — the account-existence timing
  oracle matters against a shared multi-tenant hosted DB; single-user
  self-host has nothing to enumerate. Hosted scope.
- **Token-in-logs hygiene / POST-confirm redeem interstitial** — self-host
  access logs live on the user's own machine; the interstitial is a real UX
  cost. Revisit for hosted.

## Improvements noted

- `_BodySizeCap` buffers length-less (chunked) bodies bounded at cap+1 and
  answers 413 itself, instead of raising from the receive channel: the
  routes' deliberate blanket `except Exception` around `request.json()`
  would have swallowed a raised signal and returned 400. The first
  implementation (raise + exception handler) failed exactly that way — the
  chunked test caught it.
- Pre-existing test updated, behavior strictly stronger:
  `test_magic_link_url_uses_the_configured_origin_not_the_host_header` used
  to assert a spoofed-Host request was SERVED with the config-origin link;
  TrustedHost now rejects it 400 pre-route (no token minted, no email sent)
  and the test asserts both layers.
- IPv6 `::1` deliberately absent from the default allowlist:
  TrustedHostMiddleware splits the Host header on `:`, so a bracketed IPv6
  literal could never match — documented in `_allowed_hosts`.
- `www_redirect=False` on TrustedHost: an API answers 400, never redirects
  to www.
- New config: `MCPFORWORK_DB_RUN_MIGRATIONS` (default 1) so the restricted
  PG `app` role (no DDL) can serve request-path connections; self-host
  SQLite keeps auto-migrate ergonomics. Justification: required by the
  HTTP-layer live-PG test and the hosted PG topology.
- Compose-side secret wiring (`require MCPFORWORK_SESSION_SECRET from .env`)
  stays on S6.8 — the `api` service does not exist in docker-compose.yml
  yet; the app-side fail-closed raise + test already shipped in S6.1b.
