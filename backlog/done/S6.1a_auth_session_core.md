# S6.1a — Magic-link + session auth core (pure service)

**Epic:** Sprint 6 hosted alpha — accounts (feeds the dashboard's magic-link
session per ADR 0002; unblocks the `entrypoints/api/` gap ADR 0002/0003 flag)
**Estimated effort:** ~2.5 h
**State:** pending

## Scope — the PURE core ONLY
The FastAPI `entrypoints/api/` layer AND magic-link email delivery are
DEFERRED (user-coordinated: the dashboard-brief §7 endpoint contract is absent
and the email-delivery mechanism is undecided). This card ships only the
dependency-light, fully-tested auth primitives that both a future API layer and
the CLI can call. No HTTP, no email, no `web/` contact.

## Design
- New table `magic_link_tokens` (migration v8, SQLite `MIGRATIONS` + PG
  `pg/008_*.sql`): `id`, `user_id` FK→users, `token_hash` (sha256 hex, UNIQUE),
  `expires_at`, `used_at` (nullable). **NOT FORCE-RLS'd** — it is looked up by
  `token_hash` PRE-auth (before any user context exists), exactly like
  `users`/`audit_log`. Document that; grant the PG `app` role SELECT/INSERT/UPDATE.
- `services/auth_session.py` (takes injected `now`/`secret` — no hidden clock or
  global; raw token via `secrets.token_urlsafe`):
  - `request_magic_link(uow, email, *, now, ttl_minutes=15) -> {raw_token, expires_at, user_id}`:
    find-or-create user by email; generate a random raw token; store ONLY its
    sha256 hash + expiry. Return the RAW token to the caller (to be emailed).
    The raw token is NEVER persisted.
  - `redeem_magic_link(uow, raw_token, *, now) -> {user_id} | {error}`: sha256 the
    presented token, find an UNUSED, UNEXPIRED row, set `used_at=now` (single-use),
    return `user_id`. Reject expired / already-used / unknown.
  - `issue_session(user_id, *, secret, now, max_age_s=1209600) -> str`: sign the
    user_id with itsdangerous `URLSafeTimedSerializer`.
  - `read_session(value, *, secret, now, max_age_s) -> user_id | None`: verify the
    signature + max_age; `None` on tamper/expiry/garbage.
- New dep: `itsdangerous>=2` — battle-tested HMAC-signed tokens; justification:
  do NOT hand-roll signed-cookie crypto for a security boundary.

## Definition of Done
- [x] magic-link: single-use (second redeem fails, incl. across separate
      connections), expiry enforced (incl. exact-instant), wrong/tampered/unknown
      token rejected, raw token NEVER persisted (only its sha256 hash)
- [x] session: tamper/wrong-secret/garbage/wrong-shaped-payload + expiry (incl.
      exact-instant) rejected; round-trips the user_id; secret rotation invalidates
- [x] `now` and `secret` injected (deterministic tests, no real sleeping)
- [x] both backends green (migration v8 parity, live PG pre-auth no-RLS + grant
      proven as the app role); gate 4/4
- [x] `entrypoints/api/` + email delivery explicitly OUT of scope (deferred)

## Closure (2026-07-11)
`services/auth_session.py` (pure, dep-light) + `magic_link_tokens` (migration v8,
SQLite + PG twin, NOT force-RLS'd — pre-auth lookup by token_hash, proven live as
the app role with no user context). 16 tests (14 sqlite + 2 live). 298 sqlite +
26 live PG. Gate 4/4 PASS (code/test/simplicity Sonnet 5 high, security Opus):
zero P0/P1. Mutant record (manual, no mutmut): dropping the atomic
`WHERE used_at IS NULL` guard → single-use test fails (KILLED); storing raw token
not hash → KILLED; flip expiry `<=`→`<` and session `>=`→`>` → both caught by the
added exact-instant tests (KILLED). Hardening applied in-gate from reviewer P3s at
this auth boundary: (1) **security**: `issue_session` now embeds ABSOLUTE `exp` so
lifetime is fixed at issue (was a dead `max_age_s` → fail-open on lifetime);
`read_session` guards non-dict payloads and rejects bool uid (`type() is int`);
(2) exact-equality boundary tests + cross-connection single-use test; (3)
aware-UTC `now` documented. DEFERRED to the S6.x HTTP-layer card (security
required-controls, NOT blocking this pure core): rate-limiting/abuse on
request_magic_link, no account-existence disclosure, cookie flags
(Secure/HttpOnly/SameSite)+HTTPS+CSRF, session revocation strategy, secret from a
manager + rotation runbook, keep no sensitive fields in the signed (not encrypted)
cookie, token-in-logs hygiene. Also: `INSERT ... ON CONFLICT` for the concurrent
find-or-create race.
