# W6.3 — Dashboard: autopilot policy section (L2)

**Epic:** Web / dashboard
**Estimated effort:** ~2 h

## Goal

The dashboard gains an Autopilot section under Account: the human enables,
configures, and revokes the L2 policy. Explicit consent statement at enable
time. The dashboard stays mirror-and-control-panel — it records policy, it
never fills or submits.

## Spec

- Account → Autopilot page: current policy state (enabled, min score, daily
  cap, since when), enable form (min score slider/input 0–100, daily cap
  1–50), revoke action with honest copy of what revocation means (next
  `request_submit` returns `await_human`; in-flight authorized applications
  already emitted are not recalled — say so).
- Explicit consent statement at enable time: what L2 authorizes (submits
  without per-application approval on `auto_apply_safe` boards meeting the
  policy, up to the daily cap), where it's recorded (audit log).
- Read-only list of `auto_apply_safe` boards (from packs data via the API —
  never hardcoded in the web app).
- `Api` seam: `getAutopilotPolicy()`, `putAutopilotPolicy({minScore,
  maxPerDay})`, `revokeAutopilotPolicy()`, mirrored in `http.ts` and
  `fixtures.ts`; server actions + revalidation.
- Honest empty state when no policy exists ("Autopilot is off — every
  submit is yours").
