# S5.4 — LinkedIn / URL profile import parity with CV-first

**Epic:** Self-host onboarding
**Estimated effort:** ~1.5 h

## Goal

Give LinkedIn (and GitHub/portfolio) the same CV-first CONFIRM loop as
`parse_cv`: the client opens the URL in the user's browser, pastes visible
text, the server returns contact + `setup_hints` read-only, the human
CONFIRMs, then `import_from_url_findings` writes with URL provenance.
Server never fetches LinkedIn.

## Spec

- New MCP tool `preview_url_import(url, page_text)` — read-only:
  - `url` must be `https://` (ADR 0001 / load-bearing; reject http/javascript/data)
  - runs `extract_profile_from_cv(page_text)` → `candidate` + `setup_hints` +
    `cv_text` (= page_text)
  - returns `source_url` (normalized strip); never writes the profile
  - size cap = `MAX_CV_CHARS`
- `import_from_url_findings` unchanged (confirmed write + audit)
- `/setup` + guidance: LinkedIn/GitHub/portfolio path =
  open → extract text → `preview_url_import` → CONFIRM focus →
  `import_from_url_findings(url, confirmed_fields)` (include `links` /
  `cv_text` as confirmed)
- Tests pin: https-only URL, never-writes, setup_hints present, setup prompt
  names `preview_url_import`
