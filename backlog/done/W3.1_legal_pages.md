# W3.1 — Legal pages: Privacy, Terms, Security

**Epic:** Web / public site (commercial v1)
**Estimated effort:** ~3 h

> Web-track card, branch web-v1. A commercial site taking paid subscriptions
> needs real legal pages. The footer's Privacy/Terms links are `#faq`
> placeholders today.

## Goal

Author real, GDPR-aware `/privacy`, `/terms`, and `/security` pages grounded in
the product's ACTUAL data practices, each clearly flagged as a draft pending
counsel review. Replace the footer `#faq` placeholders with the real routes.

## Spec

- **Accurate to the product, no overpromising** (security-reviewer will check):
  magic-link auth (no passwords), zero server-side LLM (no model to train on
  user data), client-side intelligence, salary floor private, optional EEO
  encrypted at rest and never scored, export/delete (GDPR), self-host = data
  never leaves the machine, Stripe as payment processor (we never see card
  data), RLS multi-tenant isolation, session cookie only (no tracking cookies).
- **Honesty markers:** a visible "Draft — reviewed by counsel before launch"
  banner on each; a "Last updated" date passed in (no `new Date()` at build —
  static string, keeps builds reproducible).
- **Shared `LegalShell`** (nav + draft banner + title/updated + prose + footer),
  no new dependency; prose via a `legal.module.css`.
- **Terms** must state: the user is responsible for applications they submit;
  must respect job boards' terms; captchas are human-solved; no employment
  guarantee; 7-day trial then $5/mo, cancel anytime; Apache-2.0 self-host.
