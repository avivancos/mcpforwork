# S2.6 — Browser-verify global-remote boards + add a search-box playbook mode

**Epic:** Sprint 2 — MCP v1 (packs) / geo expansion
**Estimated effort:** ~3 h
**State:** pending

## Goal

The S2.3 `global-remote.yaml` boards (Remotive, WeWorkRemotely, Himalayas,
Jobicy, Working Nomads, HN Hiring) were shipped with hand-written url_templates
that were NOT browser-verified. S2.5's browser pass found that these dedicated
remote boards are mostly SPAs (client-side filtering) or Cloudflare-protected —
a direct `?param={query}` URL often lands on a generic page, not filtered
results. RemoteOK was dropped in S2.5 (tag-path, incompatible with quote_plus).
Make the remote-board experience actually work.

## Spec

- Browser-verify each global-remote board's real search. For boards with a
  working query-param search, fix the `url_template`. For SPA/Cloudflare boards
  with no URL-driven search, add a **search-box playbook mode**:
  `search_playbook.mode: url_template | search_box`; in `search_box` mode the
  template is the board's search PAGE and `result_hint` tells the client to type
  `{query}` into the on-page search box (browser interaction) rather than
  navigating a pre-filled URL. `hunt_plan` returns the mode so the client knows
  which to do.
- Re-add RemoteOK via `search_box` mode (or its tag-path with a client-hyphenated
  single keyword).
- Keep the `test_no_shipped_template_puts_the_query_in_the_url_path` guard for
  `url_template`-mode sources; `search_box`-mode sources are exempt (no {query}
  in a navigable URL).
- Extend `domain/packs.validate_pack` for the new `mode` field.

## Files to create/modify

- `src/mcpforwork/packs/global-remote.yaml` — verified templates / modes
- `src/mcpforwork/domain/packs.py` — validate `mode`
- `src/mcpforwork/packs/registry.py` + `services/hunt.py` — surface mode
- `tests/` — mode validation + selection
