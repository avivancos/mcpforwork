# S6.6a — Parity API: pipeline read endpoints

**Epic:** Sprint 6 / self-host E2E — API parity (Phase 1 of the E2E plan)
**Estimated effort:** ~3.5 h

## Goal

Give the dashboard real read data: `GET /v1/pipeline`,
`GET /v1/pipeline/stats`, `GET /v1/matches/{id}` — backed by a new
`services/pipeline.py` that composes findings + applications + assets + audit
into the web contract (`web/src/lib/api/types.ts`). Also expose
`pipeline_stats` as an MCP tool (one service, two thin wrappers).

## Spec

Contract source of truth: `web/src/lib/api/types.ts` + `http.ts`. ISO-8601
timestamps, string ids; web humanizes at render.

- `services/pipeline.py` (NEW; imports only domain/ports/services):
  - `list_pipeline(uow, user_id) -> list[PipelineItem]`
  - `pipeline_stats(uow, user_id) -> PipelineStats`
  - `get_match_detail(uow, user_id, finding_id) -> MatchDetail | None`
  - Pure stage-derivation function (unit-tested): discarded → `discarded`;
    application filling → `filling`; `awaiting_human`|`submit_requested` →
    `awaiting_you`; submitted → `submitted`; verified → `verified`; outcomes
    map (`no_reply` → `no_response`); else `new_match`.
  - Audit reads MUST filter `user_id` explicitly (audit_log is not
    RLS-forced — ADR 0001 ledger).
- Routes in `entrypoints/api/app.py`: the three GETs above;
  `get_match` returns 404 when the finding is not the user's (web's
  `getOrNull`).
- MCP tool `pipeline_stats()` in `entrypoints/mcp/server.py` (thin wrapper).
- `needsYou` set when stage is `awaiting_you` (reason from the application
  state); `consent: "supervised"` once an application exists, else null.

## Improvements noted

- Deviation from the card's file list: the live-PG cross-tenant proof lives as
  a service-level parity arm (`any_uow`) in `tests/test_pipeline_api.py`
  instead of route-level cases in `tests/test_api_auth.py` — consistent with
  the existing `*_rls_live.py` suites.
- Follow-up card candidate: `pipeline_stats` derives over a 1000-row window
  and `get_match_detail` over the last 200 audit rows — silent truncation past
  those limits (fine at MVP scale; revisit with pagination).
- Review-gate fix folded in: the live-PG arm serializes with `default=str`
  (entrypoint-style) — plain `json.dumps` breaks on PG datetimes; the audit
  user_id filter test is now adversarial (foreign row references the caller's
  own finding, so only the SQL filter stands).
