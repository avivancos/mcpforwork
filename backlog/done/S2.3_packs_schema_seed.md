# S2.3 — Pack schema + validator + seed packs

**Epic:** Sprint 2 — MCP v1 (profile + hunt)
**Estimated effort:** ~4 h
**State:** pending

## Goal

Source packs are versioned DATA (country/sector), the mechanism by which the
copilot learns HOW to search each site — deployable independently of releases.
Establish a CLEAN structured schema (ISO country codes + sector tags),
replacing the donor's free-text `cat`/`region` mess, plus a validator and a
seed set of packs. Sector/country agnostic BY DATA (§5).

## Spec

- `packs/*.yaml` file shape:
  ```yaml
  pack: { id: global-remote, version: 1, kind: global|country|sector, title: ... }
  sources:
    - slug: remoteok
      name: RemoteOK
      base_url: https://remoteok.com
      countries: [global]           # ISO-3166 alpha-2, or "global"
      sectors: [any]                # sector tags, or "any"
      remote: true
      tier: free                    # free | pro
      enabled: true
      search_playbook:
        url_template: "https://remoteok.com/remote-{query}-jobs"
        result_hint: "..."          # where the results/pagination are
      apply_playbook:               # optional
        ats_hint: greenhouse
        auto_apply_safe: false
  ```
- `domain/packs.py` (PURE): `PackSource`/`Pack` typed shape + `validate_pack(data)
  -> list[str]` (errors): required fields, ISO-code shape, `url_template` must
  contain `{query}`, unique slugs, enum tiers. No I/O.
- `packs/registry.py`: load + validate all `packs/*.yaml`, return sources by
  slug; `sources_for(countries, sectors, remote)` selector used by hunt.
  `pyyaml` dependency (packs are yaml for PR-friendly community contribution).
- Seed: a clean, well-structured representative set — `packs/global-remote.yaml`
  (the enabled global/remote boards + the big ATS metas) plus `packs/us.yaml`
  and `packs/de.yaml` as country-pack examples (~25-40 sources, each with a
  search_playbook so hunt is actionable). The full 155-source donor migration
  is an ongoing PR-based data task (the plan's community model) — NOT a
  mechanical port of the messy tags.
- Validator runs in CI via pytest (a dedicated CLI validator ships with the CLI
  in S5).

## Definition of Done

- [x] `validate_pack` rejects: missing required field, bad country code,
      url_template without `{query}`, duplicate slug, unknown tier (+ non-http
      url_template/base_url, non-bool auto_apply_safe — S2 gate hardening)
- [x] Every shipped pack file loads and validates in CI (pytest)
- [x] `registry.sources_for(...)` selects by country/sector/remote correctly
      (incl. non-matching-sector exclusion)
- [x] Targeted tests green; Final-review gate 4/4 (simplicity: no messy-tag port)

## Improvements noted

- Security gate finding fixed: `url_template` (and `base_url`) must be http(s) —
  packs are untrusted and the URL is opened in the user's browser (rejects
  javascript:/data:). `apply_playbook` URL scheme validation deferred to the S4
  apply card (no live path yet; ADR 0001).
- Seeded ~13 clean sources across 3 packs, not a mechanical port of the donor's
  155 messy-tag sources — the full migration is the plan's ongoing PR task.
