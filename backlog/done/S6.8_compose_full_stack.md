# S6.8 — Compose full stack: api service + tenant-email alignment + ADR 0006

**Epic:** Sprint 6 / self-host E2E — Phase 3 of the E2E plan. The dashboard
stops running on fixtures and reads the real parity API; the whole product
boots with `docker compose up --build`.
**Estimated effort:** ~4 h

## Why

`docker-compose.yml` (ADR 0003, W1.2) ships `mcp` + `web` only, with the web
on `MCPFORWORK_FIXTURES=1` because the parity API did not exist. It does now
(S6.6a/b/c + S6.1c hardening). This card wires the real topology and makes
the MCP writer and the dashboard reader resolve to the SAME user row.

## Spec

- **ADR 0006** (`backlog/decisions/0006_selfhost_fullstack_topology.md`):
  api service, shared SQLite volume, tenant-email alignment, single-tenant
  networked-MCP caveat, cookie-secure LAN posture. Amends ADR 0003.
- **`api` service** in docker-compose.yml: same image as `mcp`;
  `uvicorn mcpforwork.entrypoints.api.app:app --host 0.0.0.0 --port 8000`;
  shares the `mcpforwork-data` volume; `MCPFORWORK_SESSION_SECRET` required
  from `.env` (compose `?` error syntax — never a baked default, per S6.1c);
  `MCPFORWORK_ALLOWED_HOSTS` documented for LAN access.
- **`web` service**: `MCPFORWORK_API_URL=http://api:8000`, drop
  `MCPFORWORK_FIXTURES`. Verify the web's fail-closed guard (ADR 0002) boots
  clean against the real API URL.
- **Tenant alignment (key)**: new `MCPFORWORK_USER_EMAIL` env (default
  `local@self-host`) naming the local MCP user's email; the human logs into
  the dashboard with that same address so magic-link find-or-create resolves
  the SAME user row the MCP writes as. The MCP server ensures the row exists
  on boot (find-or-create by email, then pin `MCPFORWORK_USER_ID` to it).
  `GET /v1/connection` already surfaces `tenantEmail` (S6.6c) — point it at
  the configured email so a mismatch is visible in the dashboard.
- **Redeem redirect**: `GET /v1/auth/redeem` responds `302 →
  MCPFORWORK_POST_LOGIN_REDIRECT` when that env is set (fixed config, never
  client-controlled), so compose login lands on the dashboard; unset keeps
  the current JSON 200 (API-only clients).
- **Single-tenant caveat**: the networked MCP over streamable-http has no
  per-connection auth — acceptable for single-user self-host on a LAN;
  multi-tenant HTTP MCP auth is hosted scope. Documented in the ADR + compose
  comment.

## Improvements noted

- `config.local_user_id()` now returns `int | None` (None = unset) so email
  resolution is the default path; the explicit pin is the escape hatch. Its
  only caller was the MCP server — no other call sites to migrate.
- `test_connection_reflects_real_activity_and_the_tenant_email`
  (test_account_api.py) updated: `tenantEmail` is now the CONFIGURED tenant
  email, not the session email — the S6.6c semantics were the placeholder.
- Compose api service sets `MCPFORWORK_ALLOWED_HOSTS=api,localhost,127.0.0.1`
  because the web container fetches `http://api:8000` (Host: api) — without
  it the S6.1c TrustedHost guard would 400 the BFF loop. `MCPFORWORK_COOKIE_SECURE=0`
  in compose (LAN http), documented flip-to-1 behind TLS.
- The real browser-on-compose verification (login via `docker compose logs
  api`, empty pipeline at :3000, findings appearing after /hunt) is the W6.1
  demo gate — deliberately not duplicated here.
- Evidence at close: targeted 15 passed · full 394 passed · live 37 passed
  (Docker postgres:16-alpine) · compose config valid with secret / clear
  error without · ruff clean · lint-imports 8/0 · zero mocks.
