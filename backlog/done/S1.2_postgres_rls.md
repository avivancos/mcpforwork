# S1.2 — Postgres adapter + RLS multi-tenancy + parity matrix

**Epic:** Sprint 1 — Data core (organ transplants)
**Estimated effort:** ~4 h

## Goal

The hosted backend: Postgres dialect with row-level-security tenant isolation,
and the SQLite/PG parity test matrix — porting the C1 lesson (user context set
before any query) and the fail-closed RLS policy design.

## Spec

**Donor (read-only reference):** `~/Desarrollo/startup-jobs-radar/`
- `src/radar/migrations/002_multitenant_pg.sql` — `ENABLE + FORCE ROW LEVEL
  SECURITY` on per-user tables; policy
  `USING (user_id = NULLIF(current_setting('app.current_user_id', true), '')::bigint)`
  — fail-closed: unset GUC → zero rows; non-superuser app role provisioned;
  pre-auth tables (`users`, `magic_link_tokens`, billing, audit) deliberately
  NOT force-RLS'd.
- `src/radar/backend.py:113-143` — `set_user_context(conn, user_id)`:
  session-scoped `set_config` on Postgres (NOT `SET LOCAL` — services commit
  mid-flow), no-op on SQLite (isolation there is app-level `WHERE user_id`).
- Tests: `tests/test_multitenant_isolation.py`, `tests/test_api_rls_live.py`
  — live tests connect AS the non-superuser role to exercise FORCE RLS.

**Target shape:**
- `adapters/db/backend.py` gains the psycopg v3 path (`dict_row`).
- Parity matrix: shared fixture
  `@pytest.fixture(params=["sqlite", pytest.param("postgres", marks=pytest.mark.live)])`
  in `tests/conftest.py`; `TEST_POSTGRES_URL` env with a documented
  `docker run` one-liner for the local instance.
- RLS probe test: two users, each sees only their rows on every per-user
  table; unset context sees nothing (fail-closed proven, not assumed).
