# S7.2c — Apply playbooks in packs + auto_apply_safe curation

**Epic:** Packs / data
**Estimated effort:** ~3 h (+ human browser verification)

## Goal

Packs gain `apply_playbook` data (`ats_hint`, `quirks`) for verified boards,
and `auto_apply_safe: true` is set ONLY where a native, login-free,
non-hostile form was verified by a human in a real browser. Expect few —
that conservatism is the product's risk posture. Clients will now open
playbook URLs, so scheme validation becomes load-bearing.

## Spec

- Pack schema: `apply_playbook` mapping per source (optional):
  `ats_hint` (string), `quirks` (list of strings), `form_url_pattern`
  (https only). Validator enforces shape + https scheme for any URL field
  (closes the ADR 0001 follow-up — now load-bearing because agent clients
  will open these URLs).
- `auto_apply_safe: true` per source ONLY after human browser verification
  of: native form (no iframe ATS redirect), no login wall, no
  CAPTCHA/hostile automation countermeasures, submit button reachable
  without scrolling tricks. Evidence recorded on this card per source.
- `domain/packs.validate_pack` rejects non-https playbook URLs and unknown
  `apply_playbook` keys; tests pin both.
- Guidance: `/apply` reads the pack's playbook when present (quirks surface
  in the fill plan); absence of playbook = L0 behavior unchanged.

## Files to create/modify

- `src/mcpforwork/domain/packs.py` — schema + https validation
- `src/mcpforwork/packs/**/*.yaml` — playbook data + `auto_apply_safe`
  flags (only human-verified sources)
- `tests/test_packs.py` — validator tests (scheme, unknown keys)
- `docs/modules/packs.md` — document the playbook contract
