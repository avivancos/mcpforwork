# W2.1 — Docs content system + Getting-started + Core-concepts + FAQ

**Epic:** Web / public site (commercial v1)
**Estimated effort:** ~4 h

> Web-track card, branch `web-v1` (worktree). Turns the single Quickstart page

> ship as "coming soon" and are seeded as follow-up card W2.2.

## Goal

Replace the one hardcoded `/docs` page (15 dead `href="#"` sidebar stubs, fake
search) with a route-per-page docs system, and author the high-value pages:
Getting-started (Quickstart, Connect to Claude, Connect to ChatGPT, Build your
profile) and Core-concepts (Facts inventory, Consent levels L0–L2, Regional
packs, Scoring & constraints, Dedup & tracking). Add a standalone `/faq` fed by
a shared content module. Reference + Self-hosting sidebar items render as
"coming soon" (no dead links).

## Spec

- **No new dependency** (charter): route-per-page under `src/app/docs/<slug>/`,
  a shared server `DocsShell` component (nav + sidebar + content + on-this-page
  TOC + prev/next), and a `_nav.ts` config with real slugs + an `available`
  flag. Active sidebar state from the page's `slug` prop (server-rendered, no
  client hook). Design inherits `docs.module.css` + `globals.css` tokens.
- **Content is accurate to the product** (PRODUCT_PLAN): zero server-side LLM,
  facts inventory as the only claimable source, consent L0/L1/L2, packs as
  versioned data, canonical-URL dedup, sector-pack scoring. No invented
  features; "coming soon" is honest.
- **FAQ**: extract the landing's Q&A to `src/content/faq.ts` (shared, no drift);
  `/faq` renders the full grouped set; the landing section imports the same
  source; footer gains an FAQ link.
- **Wiring**: sidebar/TOC/prev-next links resolve to real routes; no `href="#"`
  in shipped docs; the fake "⌘K search" stays visual-only and `aria-hidden`
  (real search = follow-up).

## Final-review gate — reviewer dispositions

All four reviewers **PASS** (branch web-v1). No P0/P1.

- **P2 (test-auditor, fixed):** `DocsShell.slug` was typed `string`, so a typo'd
  slug in a future page would silently drop breadcrumb + prev/next. Fixed by
  deriving a `DocSlug` literal union in `_nav.ts` and typing the prop + every
  `DocItem.slug` as it — a slug typo is now a compile error (no test harness, no
  dep; charter-aligned). Typecheck confirms all 9 page slugs satisfy it.
- **P3 (code + security + simplicity, verified intentional):** the landing FAQ
  now renders all 11 shared items (was a curated 8) via `FAQ_FLAT`. Deliberate —
  one content source, more FAQ is good for a commercial page. Browser-verified:
  11 questions render (incl. the 3 new), section 1294px, no layout break, and a
  "Read the full FAQ → /faq" link added.
- **P3 (deferred to W3):** footer Privacy/Terms still `#faq` placeholders —
  pre-existing, W3 (legal pages) replaces them.
- **P3 (noted):** "7-day trial" copy — a resolved user directive (trial→$5),
  supersedes the PRODUCT_PLAN open item.

Verification: build (9 docs routes + /faq static) · tsc · guard green;
