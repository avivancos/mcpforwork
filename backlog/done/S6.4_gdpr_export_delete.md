# S6.4 — GDPR export_user_data / delete_user_data + audit_log read-scoping

**Epic:** Hosted alpha — data-subject rights (carried ADR-0001 S1-gate item)
**Estimated effort:** ~2 h
**State:** in_progress

## Goal
Data portability + erasure over the full per-user data model, and close the
carried audit_log read-scoping item: `audit_log` holds per-tenant data (applied
URLs) and is deliberately NOT FORCE-RLS'd, so every read path over it MUST scope
by `user_id`.

## Design
- `services/privacy.export_user_data(uow, user_id) -> dict`: the `users` row plus
  every per-user table (profiles, achievements, style_profile, explore_findings,
  external_applications, generated_assets, applications, playbook_reports,
  audit_log) filtered by `user_id`. Read-only, JSON-serializable.
- `services/privacy.delete_user_data(uow, user_id) -> dict`: delete every per-user
  row in FK-safe child→parent order, then the `users` row; returns per-table
  counts. Caller commits. (No post-delete audit row: the user's audit_log is
  itself erased and the FK to a deleted user would fail — erasure leaves no
  trace, which is GDPR-correct for self-host.)
- One ordered `_USER_TABLES` constant (trusted internal identifier list) drives
  both, so the two never drift. `users` handled separately (scope by `id`).
- MCP tools `export_my_data()` (read-only) and `delete_my_data(confirm)` — the
  destructive one refuses unless `confirm=True` (an LLM client must never wipe
  the user's data by accident).

## Definition of Done
- [x] export gathers all per-user tables scoped by user_id; a second user's rows
      never leak (audit_log applied-URL included) — the carried scoping item
- [x] delete removes every per-user row + the users row, FK-safe; other users'
      data untouched; idempotent (second delete = all-zero counts)
- [x] delete_my_data refuses without confirm=True; both tools registered;
      tool-layer fresh-connection check
- [x] both backends green; gate 4/4
