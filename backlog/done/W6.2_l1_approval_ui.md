# W6.2 — Dashboard: approve-submit action (L1)

**Epic:** Web / dashboard
**Estimated effort:** ~2 h

## Goal

The dashboard becomes the L1 control panel: a human approves the submit of an
application that is waiting on them. The dashboard approves — it never fills
or submits (mirror-and-control-panel invariant).

## Spec

- `types.ts`: `consent` widens to `"supervised" | "autopilot_l1" | "autopilot_l2" | null`.
- `Api.approveSubmit(id)` → `POST /v1/applications/{id}/approve-submit`,
  mirrored in `http.ts` and `fixtures.ts`.
- Match detail page: when the application is `awaiting_you` (state
  `submit_requested`), an "Approve submit" action with explicit copy of what
  approval means (one application, one submit, recorded in the audit log).
- Pipeline table: the chip for an L1-approved application reflects the
  approval; after `confirm_submitted` the row shows `consent: autopilot_l1`.
- Optional: pipeline multi-select approve — only if it stays a thin loop over
  the single-approve action (rule of two; otherwise skip).
- Server action in `web/src/lib/actions.ts` + revalidation.
