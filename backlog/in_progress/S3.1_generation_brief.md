# S3.1 — get_generation_brief: extraction, keyword map, facts inventory

**Epic:** Sprint 3 — Assets: briefs + honesty engine
**Estimated effort:** ~4 h
**State:** pending

## Goal

The structured brief the client LLM drafts from. The server never generates
text — it assembles deterministic structure: what the posting asks for, and the
FACTS INVENTORY (only claims the profile proves). Gaps are acknowledged, never
stuffed (§4 never-fabricate, made structural).

## Spec

- `domain/brief.py` (PURE): `extract_keywords(title, description) -> list[str]`
  (deterministic term extraction: frequency + title boost, stopwords out, no
  LLM); `build_facts_inventory(profile, achievements) -> dict` — the ONLY
  claims the drafter may use: identity, titles, sectors, seniority, languages,
  links, achievements (metric+context+role), cv_text. Salary NEVER included
  (privacy gate upstream).
- `services/briefs.py`: `get_generation_brief(uow, user_id, finding_id,
  asset_type)` → `{job: {title, company, url, keywords[]}, facts_inventory,
  style: {writing_sample?, directives?}, honesty_rules[], format: {template:
  print-css-a4, medium: markdown}, language_hint, next_action}`. asset_type ∈
  {cv, cover_letter}. Errors as `{error}` (unknown finding, no profile).
- honesty_rules are fixed strings: only facts_inventory claims; acknowledge
  gaps; never invent employers/dates/metrics.
- MCP tool `get_generation_brief(finding_id, asset_type)`.
