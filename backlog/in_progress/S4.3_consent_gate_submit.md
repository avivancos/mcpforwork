# S4.3 — request_submit L0 consent gate + confirm_submitted + outcomes

**Epic:** Sprint 4 — Browser-apply orchestration
**Estimated effort:** ~3 h
**State:** pending

## Spec

- `services/apply.py`:
  - `request_submit(uow, user_id, application_id, summary="")` — THE only
    submit path. L0 (the only level until S7): returns
    `{decision: await_human, instruction: show the filled form; the HUMAN
    clicks Submit}`, state → awaiting_human. Audited with the summary.
    NEVER returns submit_authorized in this sprint (structural test).
  - `confirm_submitted(uow, user_id, application_id, evidence="")` — the human
    confirmed they submitted: state → submitted, `record_application(url)`
    (dedup hash, finding flip), audit with evidence; then verify step →
    state `verified` optional via report_apply_progress.
  - `record_outcome(uow, user_id, application_id, outcome:
    no_reply|rejected|interview|offer|hired, notes="")` — stores outcome on the
    application (calibration seed), audited.
- `get_asset_file(uow, user_id, asset_id)` — writes the asset content to
  `config.data_dir()/assets/<id>_<type>.md` and returns the path (self-host
  local file for uploads; hosted signed URLs arrive with the hosted sprint).
- MCP tools for all four.

## Definition of Done

- [ ] request_submit at L0 ALWAYS returns await_human; grep/property test: no
      code path yields submit_authorized in this sprint
- [ ] confirm_submitted flips state, records the application (check_seen now
      skips the URL), writes audit with evidence
- [ ] record_outcome persists; invalid outcome rejected
- [ ] get_asset_file writes under data_dir and returns a readable path
- [ ] Foreign ids rejected everywhere; gate 4/4
