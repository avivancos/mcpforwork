# W1.2 — Docker images + compose (web + MCP self-host)

**Epic:** Web / packaging (pull-forward of S5.3 self-host image + hosted deploy prep)
**Estimated effort:** ~2 h

> User-directed (2026-07-11): containerize the whole product — bring up the
> W1.1 web surfaces alongside the Python MCP server via `docker compose`.
> See ADR `backlog/decisions/0003_docker_compose.md`.

## Goal

A root `docker compose up` that runs the Next.js web surfaces (:3000) and the
Python MCP server as a networked connector (:8000/mcp), sharing one SQLite
volume. Honest about the S6.x gap: the dashboard runs on fixtures until the
FastAPI parity API exists.

## Spec

- **`mcp` service** — root `Dockerfile` (uv, multi-stage). Runs
  `mcpforwork-mcp` with `MCPFORWORK_TRANSPORT=streamable-http`,
  `FASTMCP_HOST=0.0.0.0`, `FASTMCP_PORT=8000`, `MCPFORWORK_DATA_DIR=/data`.
  Non-root; `/data` on the `mcpforwork-data` named volume; `EXPOSE 8000`.
- **`web` service** — `web/Dockerfile` (Next standalone, multi-stage). Serves
  landing/docs/dashboard on `:3000` with `MCPFORWORK_FIXTURES=1` (no parity API
  yet; the fail-closed guard needs it). `MCPFORWORK_API_URL` present but
  **commented** — uncommenting flips the dashboard onto the real backend at S6.x.
- **Isolation:** root `.dockerignore` excludes `web/`, `.venv/`, tests, VCS;
  `web/.dockerignore` excludes `node_modules/`, `.next/`, VCS. Additive —
  no Python source, CI, or test change.
- **Verify:** `docker compose build` both images; `up -d`; `curl :3000` → 200;
  `:8000/mcp` reachable (any HTTP response = process up); `down`.
