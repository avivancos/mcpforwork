# S2.4 — hunt_plan + submit_findings + sector-driven scoring + list_matches

**Epic:** Sprint 2 — MCP v1 (profile + hunt)
**Estimated effort:** ~5 h
**State:** pending

## Goal

The search side of the copilot: from the user's profile + packs, produce
per-source search playbooks the client LLM browses; ingest the findings it
extracts (deduped, scored, persisted); surface the matches. Scoring is
PROFILE- and SECTOR-PACK-driven — NOT the donor's hardcoded tech persona.

## Spec

- Migration v4: `explore_findings` (id, user_id, source_slug, dedup_hash UNIQUE
  per user, url, title, company_name, location, remote_scope, salary_text,
  description, score, score_breakdown, status, action, first_seen, last_seen) +
  FORCE RLS. Add the deferred `external_applications.finding_id` FK →
  `explore_findings(id)` (SQLite table-recreate; PG `ADD CONSTRAINT`). The
  fail-closed RLS test (S1) must still pass after the recreate.
- `domain/scoring.py` (PURE): `score_finding(finding, profile, sector_terms=())
  -> (int, dict)`. Signals from the PROFILE (target_titles + sectors tokenized)
  and optional sector-pack terms — title/keyword overlap, work-mode/remote
  match, salary-mention, seniority — combined to 0-100 with a breakdown.
  `determine_action(score)` → new | review | strong. No hardcoded tech lists.
- `services/hunt.py`:
  - `hunt_plan(uow, user_id)` — active profile → select pack sources by
    country/sector/remote → build search URLs from `url_template` (`{query}` =
    target titles) → `[{slug, name, search_url, result_hint, apply_hint}]`.
  - `source_playbook(slug)` — the pack entry (search + apply) for one source.
  - `submit_findings(uow, user_id, source_slug, findings)` — for each: skip
    blank/dup (check_seen over external_applications AND explore_findings),
    score via `score_finding` with the active profile, upsert into
    explore_findings; return `{submitted, new, seen_again, scored}` stats.
  - `list_matches(uow, user_id, min_score=0, status=None, limit=50)` — findings
    ordered by score desc.
- Extend `services/dedup.check_seen` to also consult `explore_findings` now that
  it exists (status/source in the item), and `record_application` to link a
  finding by hash + flip it to `applied_external` (restore the S1.4-cut paths).
- MCP tools: `hunt_plan`, `source_playbook`, `list_sources`, `submit_findings`,
  `check_seen`, `list_matches`, `get_match` + the `/hunt` prompt.
