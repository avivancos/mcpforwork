# S2.1 — FastMCP stdio entrypoint + server_info + guidance breadcrumbs

**Epic:** Sprint 2 — MCP v1 (profile + hunt)
**Estimated effort:** ~3 h
**State:** pending

## Goal

Stand up the MCP server (the product's primary interface) over stdio, so a
self-host client (Claude Code / Desktop) can connect with zero account. Every
tool response carries a `next_action` breadcrumb, and `server_info` is the
version/capability handshake. This is thin wiring — no business logic beyond
opening a tenant-scoped UnitOfWork per call.

## Spec

- `mcp>=1.2` dependency (core — the MCP server IS the self-host product). Use
  the SDK's bundled `from mcp.server.fastmcp import FastMCP`.
- `entrypoints/mcp/server.py`: one module-level `mcp = FastMCP("mcpforwork",
  instructions=SERVER_INSTRUCTIONS)`. Tools are `@mcp.tool()` functions
  returning `json.dumps(...)` strings. `main()` runs `mcp.run(transport=...)`,
  default stdio; console script `mcpforwork-mcp`.
- `_uow()` helper: `connect(config.db_url())` → resolve local user
  (`config.local_user_id()`, env `MCPFORWORK_USER_ID` default 1) → ensure that
  user row exists (idempotent, self-host convenience) → `set_user_context` →
  return `(uow, user_id)`. Per-tool body: `try/… finally: uow.close()`.
- `entrypoints/mcp/guidance.py` — DEPENDENCY-FREE (imports no other layer):
  `SERVER_INSTRUCTIONS` (the behavioral contract: client-side browsing only,
  server never fetches/scrapes, never auto-submit — §2 invariant, human
  confirms every send/apply) and `next_action(tool_name) -> str` from a static
  dict.
- `src/mcpforwork/config.py` (package root, cross-cutting): `db_url()`
  (env `MCPFORWORK_DB_URL`, default `sqlite:///<data_dir>/mcpforwork.db`),
  `data_dir()`, `local_user_id()`.
- `server_info` tool → `{version, tools: [...], invariants: [...]}`.
